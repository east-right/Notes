> LLM Inference를 파기 전에 깔아둬야 하는 배경. "GPT/Llama가 애초에 어떻게 생겨먹었고 어떻게 학습되는가" → 이게 인퍼런스 동작(prefill/decode/KV cache)의 전제가 된다.

## 0. 큰 그림 — Transformer 3분류
원조 Transformer(2017, _Attention is All You Need_)는 **번역용 encoder-decoder** 구조. 여기서 3계열로 갈라짐.
![](assets/Pasted%20image%2020260711201751.png)

|계열|대표|학습 방식|attention|잘하는 것|
|---|---|---|---|---|
|**Encoder-only**|BERT|MLM (빈칸 채우기)|양방향(bidirectional)|이해 (분류, 임베딩, 검색)|
|**Decoder-only**|GPT, Llama|CLM (다음 토큰 예측)|단방향(causal)|생성|
|**Encoder-Decoder**|T5, BART|seq2seq|혼합|번역, 요약|

> ⚠️ 셋 다 "language model"이다. `decoder = LM`이 아니라, 우리가 요즘 말하는 **"생성형 LLM"이 decoder-only autoregressive 계열**인 것.
---

## 1. Decoder-only 등장 배경
![](assets/Pasted%20image%2020260711201818.png)
- 원조 Transformer는 encoder-decoder(번역기). GPT가 **"decoder 블록만으로 충분하다"**를 증명하며 단순화.
- decoder-only의 강점:
    - 구조 단순 → **스케일링이 쉬움**.
    - 목표가 "다음 토큰 예측" 하나로 단일 → 학습이 깔끔.
    - 그런데도 **in-context learning**(예시 몇 개 주면 따라 함) 같은 창발 능력 등장.
- 그래서 요즘 생성형 LLM은 거의 다 decoder-only로 수렴.

## 2. 아키텍처 — 핵심은 이름이 아니라 mask
![](assets/Pasted%20image%2020260711211241.png)
![](assets/Pasted%20image%2020260711211255.png)

"decoder"라는 이름은 역사적 유산. encoder 블록과 decoder 블록은 (cross-attention 빼면) 구조가 거의 같다. **진짜 차이는 attention mask 하나.**

- **Encoder (BERT)**: 양방향. 각 토큰이 **앞뒤를 다 봄**.
- **Decoder (GPT)**: **causal mask**. 각 토큰이 **자기 + 왼쪽(과거)만** 봄. 미래는 가려짐.

```
위치1 (나는):    "나는"만 봄
위치2 (오늘):    "나는", "오늘" 봄
위치3 (학교에):  "나는", "오늘", "학교에" 봄
위치4 (갔다):    "나는", "오늘", "학교에", "갔다" 봄
```

이 시야 제한이 **하삼각(lower triangular) 행렬** 형태의 mask로 구현된다.

![](assets/Pasted%20image%2020260711211306.png)

> 💡 양방향은 문맥 전체를 보니 **이해**에 강하고(BERT), 단방향은 "지금까지 보고 다음 예측"이라 **생성**에 맞다(GPT).

## 3. 학습 방법 — CLM (Causal Language Modeling)

**한 줄: 다음 토큰 예측. 그게 전부.**

### 3-1. (input, target) 만들기 — label을 한 칸 shift
![](assets/Pasted%20image%2020260711211325.png)

```
Input  (모델이 봄):   나는    오늘    학교에   갔다
Target (맞춰야 함):   오늘    학교에   갔다    <EOS>
```

- 각 위치의 정답 = "바로 다음 토큰".
- 정답이 그냥 입력을 민 것이라 **별도 라벨링 불필요** → 인터넷 텍스트 = 학습 데이터 (**self-supervised**).

### 3-2. 통째로 넣되, causal mask로 컨닝 방지
![](assets/Pasted%20image%2020260711211340.png)

- 문장 전체를 **한 번에** 넣는다(병렬). 포지션 임베딩으로 위치 정보도 넣음.
- "정답이 입력에 있는데 어떻게 학습되지?" → **causal mask가 가려서, 예측할 위치에서는 정답이 안 보인다.**

### 3-3. Teacher Forcing
- = "정답 시퀀스(teacher)를 다음 입력으로 강제로(forcing) 먹여준다."
- 학습 땐 모델이 앞에서 틀렸든 말든, **다음 위치엔 무조건 진짜 정답**을 넣는다.
- **★ 핵심: 학습엔 "생성 → 다시 입력" 루프가 없다.**
    - 정답 문장 전체를 이미 아니까, 처음부터 통째로 넣고 각 위치가 병렬로 다음을 예측.
    - "prompt + 이전에 생성한 단어"를 넣는 게 아님. 그건 추론 얘기.
    - 생성한 걸 다시 넣을 이유가 없다 — 정답을 아는데 왜 자기가 만든 걸 넣나? 그냥 정답을 넣지.

### 3-4. 한 번의 forward로 모든 위치 동시 예측 → loss

- 4개 위치 예측이 **한 번의 forward pass에서 동시에** 나옴.
- 각 위치가 어휘 전체 확률분포를 뱉음 → 정답 토큰과 **cross-entropy** 비교.
- 모든 위치 loss의 **평균** = 문장 loss → 역전파.

> 💡 **문장 하나 = 학습 신호 여러 개.** 4토큰 문장이면 예측 문제 4개가 공짜.
### 3-5. Exposure Bias (teacher forcing 약점)

- 학습: 왼쪽 문맥이 **항상 진짜 정답**.
- 추론: 자기가 생성한(틀릴 수도 있는) 걸 다음 입력으로 씀 → 오류 누적 가능.
- 이 학습↔추론 간극이 **exposure bias**. (스케일 커지면 대체로 완화. 개념만.)

## 4. 평가 — 학습 결과 어떻게 보나
**1. 학습 중 지표**
- **Loss**: cross-entropy. train/val 둘 다.
- **Perplexity(PPL)** = exp(cross-entropy). "다음 토큰 고를 때 평균 몇 개 중에 헷갈리나". 낮을수록 좋음.

**2. 실제 능력 평가 — 벤치마크**
- loss/PPL는 지능과 완벽히 비례하진 않음 → 다운스트림으로 확인.
- **HellaSwag**(상식), **MMLU**(지식), **GSM8K**(수학), **HumanEval**(코딩) 등.

> pretrain은 여기까지(다음 토큰 예측만). 이후 **SFT → RLHF**가 붙어야 챗봇이 됨.

## 5. 추론 — Autoregressive 생성
### 5-1. ★ "개념적" vs "실제" — 별개의 두 시스템이 아니다
가장 헷갈리는 지점. 둘은 **같은 결과를 내는 두 계산 경로**일 뿐이다.
**개념적으로 (autoregressive의 정의):** 매 스텝 지금까지의 전체 시퀀스를 넣어 다음 하나를 뽑는다.
- 내가 가장 헷갈린 지점은 디코딩 단계에서 Autoregressive를 진행한다고 했을 때 다음 예측을 **디코딩된 단어만 넣어서 진행하냐** 아니면 **step마다 진행된거 전부 다 넣어서 진행하냐로 헷갈렸다.**

```
[prefix]          → t1
[prefix, t1]      → t2
[prefix, t1, t2]  → t3
```

논리적으론 매 스텝 전체가 관여. 이건 맞는 정의.

**근데 실제로 이렇게 매 step 계산하면 미친 낭비다 → 그래서 KV cache:** `[prefix, t1]`을 통째로 다시 넣으면 prefix의 K,V를 또 계산. 근데 이미 계산했고, causal mask 때문에 **뒤에 t1이 붙어도 prefix의 K,V는 안 변한다.** → 재계산은 순수 낭비.

**실제 (KV cache):** 이미 계산한 K,V를 저장해두고, **모델 입력으로는 새 토큰 1개만** 넣는다.

```
prefill:  [prefix] 통째로 한 번 Q,K,V 계산 → K,V 저장 → FFNN → t1
decode1:  [t1] 1개만 Q,K,V → t1의 K,V만 저장 → 저장된 전체로 attention, FFNN → t2
decode2:  [t2] 1개만 Q,K,V → t2의 K,V만 저장 → 저장된 전체로 attention, FFNN → t3
```

> **핵심: attention은 전체를 보지만(cache 덕분), 새로 계산하는 건 매번 새 토큰 1개뿐.** "전체를 다시 넣는" 효과는 나되, 재계산은 안 함. **출력 토큰은 둘 다 완전히 동일.** cache는 결과를 바꾸는 게 아니라, 이미 한 계산을 안 하려고 저장해두는 것.

### 5-2. 학습 vs 추론 — 루프 유무로 기억

```
학습        = 정답 있음 → 루프 없음 → 한 방에 병렬  (= prefill과 같은 원리)
추론 decode = 정답 없음 → 루프 있음 → 하나씩 순차   (근데 KV cache로 새 토큰만 계산)
```

## 6. Prefill 단계 

### 정의
입력 프롬프트(prefix) 전체를 **한 번의 forward로 병렬 처리** → 1. 프롬프트 구간 KV cache를 채우고 2. 첫 출력 토큰 1개.

### 왜 병렬 가능?
프롬프트는 **이미 다 주어진 입력**(미지수가 아님)이라 동시에 처리 가능. (decode는 다음 토큰을 모르니 순차)

### 성격
- **compute-bound** (연산량 병목, GPU 빡세게).
- 지표: **TTFT** (Time To First Token — 엔터 치고 첫 글자까지).

### ★ GPU 용량 계산 (프롬프트 1000토큰 기준)

```
입력:   1000토큰 한 번에
mask:   1000×1000 하삼각 행렬 "1장" (각 행 = 한 토큰의 시야)
계산:   1000개 토큰의 Q,K,V를 "병렬로 한 방에" (= 1000개분, 순차 아님)
결과:   ① 1000개분 K,V를 cache에 저장  ② 마지막 위치(P1000) 출력 → 첫 토큰
```

- mask는 1000개가 아니라 **1000×1000 행렬 1장**. (각 행이 한 토큰 시야)
- KV cache 크기 = **토큰수 × 레이어수** (32층이면 1000×32×K,V...). → 다음 노트의 "메모리 폭발" 씨앗.

### ★ 왜 prefill에도 mask를 씌우나? ("프롬프트는 다 아는 입력인데 왜 P1이 P2를 못 봐?")
![](assets/Pasted%20image%2020260711211649.png)
- 모델은 학습 때 **"각 위치는 왼쪽만 본다"로만 수십억 번 학습**됨. 가중치 전체가 그 전제 위에 있음.
- P1이 P2·P3를 보게 하면 → 모델이 **한 번도 본 적 없는 입력** → P1 표현이 학습 때와 달라짐 → 첫 토큰 예측 망가짐.
- "다 주어졌다"는 **사람 관점**이지 모델 관점이 아니다. 모델은 그냥 학습된 규칙대로 계산.
- 또한 이렇게 해야 **decode와 일관성** 유지 (prefill에서 만든 K,V를 decode가 그대로 재사용하니까).
- P1·P2를 처리하는 이유 = 걔네 K,V를 만들어 **P3와 이후 생성 토큰들이 참조**하게 하려고.

## 7. Decode 단계 (심화) — 한 스텝에서 정확히 뭐가 도나

새 토큰 1개(t1)만 입력. 이때 **누구 걸 계산하나?**

| 새 토큰 (t1)    | 과거 토큰 (P1~P1000) |                    |
| ------------ | ---------------- | ------------------ |
| Q (쳐다보기)     | ✗ 안 함            | ✓ 계산               |
| K, V (보여지기)  | ✗ **cache에서 꺼냄** | ✓ 계산               |
| attention    | ✗                | ✓ (t1의 Q × 전체 K,V) |
| FFN (출력 만들기) | ✗ 안 함            | ✓ 계산               |

→ **Q도 FFN도 K,V도 전부 새 토큰(t1)만.** 과거 토큰은 K,V조차 재계산 안 하고 cache 참조만.

**왜 과거 토큰의 Q·FFN은 필요 없나 — Q와 K,V의 비대칭**
- **Q** = "다음을 예측하려고 남을 **쳐다보는 시선**"
- **K,V** = "남한테 **보여지는 내용**"
- 지금 예측 대상은 **t1의 다음** 하나뿐.
    - 쳐다봐야 하는 건 t1만 → **Q는 t1만**.
    - 과거 토큰은 "보여지는 대상"으로 **K,V만 제공** → 그건 cache에 있음.
    - FFN(출력 생성)도 지금 필요한 건 t1 위치 하나 → 과거 FFN 불필요.

> **한 줄: 과거는 "보여지는 재료(K,V)"만 제공(=cache), 새 토큰만 "보고·출력하는" 전 과정(Q·K·V·attention·FFN)을 1개 위치분 계산.**
> 그래서 결국 디코딩에선 첫 단어 생성때는 prefix 전체를 보고 딱하나 생성하면 그 뒤는 새롭게 생성된 

### Decode attention이 실제로 하는 계산 (Q·K → 점수 → V 가중합)
attention은 "비교"라기보단 **"Q가 각 K랑 얼마나 맞는지 점수 매기고 → 그 점수로 V들을 가중합"**하는 것.

예) `"서울은"` 다음을 예측할 때:

```
"서울은"의 Q · "너는"의 K → 점수 (얼마나 관련?)  
"서울은"의 Q · "질문"의 K → 점수  
"서울은"의 Q · "말해줘"의 K → 점수  
...  
→ 이 점수들로 각 토큰의 V를 가중합 → "서울은"이 문맥에서 뽑아낸 정보  
→ 이걸로 다음 토큰 예측
```

- **K** = "나(과거 토큰)를 검색할 때 쓰는 키" → 새 토큰의 Q와 내적해서 **관련도 점수**를 냄.
- **V** = "관련 있다고 판정되면 실제로 전달할 내용" → 점수로 **가중합**됨.
- 그래서 새 토큰이 "앞 문맥에서 뭘 참고할지" 정하려면 과거 토큰들의 **K(점수용) + V(내용용)가 둘 다** 필요 → 그게 cache에 저장돼 있음.

### 왜 이름이 "KV" cache인가 (Q는 왜 저장 안 하나)

- **과거 토큰의 Q?** → Q는 "그 토큰이 남을 쳐다볼 때" 쓰는 것. 근데 과거 토큰들은 이미 자기 쳐다보기(prefill 때)를 끝냈고, 지금 쳐다보는 건 새 토큰뿐. → **과거 Q는 다시 쓸 일 없음 → 저장 안 함.**
- **과거 토큰의 K,V?** → 새 토큰이 계속 쳐다볼 대상 → **저장(cache).**

> **그래서 Q cache가 아니라 KV cache다. "보여지는 쪽"의 재료(K,V)만 저장하고, "보는 쪽"의 Q는 매번 새 토큰 것만 그때그때 만든다.**

### 레이어 관점 (완전히 굳히기)

32층이면 decode 스텝 = **t1 1개가 32개 레이어를 통과**하는 forward 1번.

```
각 레이어: t1의 Q,K,V 계산 → attention(t1의 Q × [그 레이어 과거 K,V(cache) + t1 새 K,V]) → FFN → 다음 층
```

- 각 레이어마다 t1의 K,V를 그 레이어 cache에 **추가**.
- 과거 1000토큰은 **어느 레이어에서도** 다시 계산 안 함 (모든 층의 과거 K,V가 cache에 있음).
- 즉 prefill = "1000토큰이 전체 레이어 통과", decode = "1토큰이 전체 레이어 통과".

### 성격
- **memory-bound** (연산 적고, weight·cache 메모리 왕복이 병목).
- 지표: **TPOT / ITL** (Time Per Output Token).

## 8. ★ causal mask의 진짜 역할 (통합 정리)
가장 자주 오해: "추론 땐 미래가 아직 안 나왔는데 왜 mask?"

**mask는 "추론 때 미래를 가리는 도구"가 아니다.** 모델을 **"각 토큰이 왼쪽만 보도록" 만드는 구조**이고, 이건 **학습 때 새겨져서 추론은 그 모델을 쓸 뿐**이다.

- **Decode**: 미래가 아직 없으니 "가릴 게 없다"는 말은 맞음. mask가 실질적으로 할 일 없음(이미 구조가 박혀 자동으로 causal).
- **Prefill**: 프롬프트를 병렬로 넣으니 **미래(뒷부분)가 존재** → mask가 실제로 작동.

**그리고 이 causal 구조가 바로 KV cache를 가능하게 한다:**

- 각 토큰 표현(K,V)이 "왼쪽만 반영한 값" → **오른쪽에 뭐가 붙어도 불변** → 저장해서 영원히 재사용 가능.

| GPT (causal)      | BERT (양방향) |       |
| ----------------- | ---------- | ----- |
| 각 토큰이 보는 것        | 왼쪽만        | 앞뒤 전부 |
| 새 토큰 붙으면 과거 표현    | **안 변함**   | 다 바뀜  |
| KV cache          | **가능**     | 불가능   |
| autoregressive 생성 | 가능         | 불가능   |

> **결론: causal mask는 단순 "컨닝 방지"를 넘어, autoregressive 생성과 KV cache 자체를 성립시키는 전제다.**
