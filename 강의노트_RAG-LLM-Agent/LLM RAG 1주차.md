## 임베딩이야기

- RAG는 검색증강이다.

- 검색이 무조건 들어가 있는게 RAG이다.

- 모델은일반적으로 최신 지식은 모른다.

- rag할 때 임베딩이 중요하다.

- 임베딩도 api형식 혹은 그냥 다운받아서 쓰는 방식 두개이다.

- 임베딩 모델도 기본적으로 모델이다.

- 임베딩 모델도 파인튜닝 = 직접 도메인에 맞게 학습하여 성능 최적화

- 한국어 잘하는 임베딩 모델 대표 = bge-m3 이건bert기반임

- gpt기반 임베딩 모델은 생성 파트에선 좋아 하지만 임베딩에는 낭비에 RAG는 안맞음

- RAF와 임베딩의 관계는 둘이 거진 같이 간다.

- 텍스트 유사도를 기반으로 검색기를 찾기에 이게 좋아야 RAG가 좋은거다.

  > 내가 할 질문 Faiss의 유사성 검색 알고리즘들인 HNSW나 LSH+PQ는 RAG시에는 HNSW나 LSH+PQ 과 같은 ANN 기반 알고리즘 들은 사용하지 않나?

- 보통 내적 코사인 유사도를 사용한다.

- 임베딩 모델이 좋으면 단어가 겹치는게 없어도 의미적으로 해석하여 임베딩을 해서 유사도를 구한다.

- 이게 기존의 검색엔진이랑 다른게, 기존 검색 엔진은 같은 단어를 기반으로 찾는다. 이걸 키워드 기반이라고 한다.

- 이러한 검색 성능을 높히기 위해서 파인튜닝을 한다.

- RAG 요즘 하이브리드 서치 많이 사용한다.

  - 덴스벡터 검색 = 임베딩(단어문장)
  - 키워드 기반 = 스펄스벡터
  - 이걸 혼합하여 검색 = 하이브리드 서치 혹은 앙상블 서치

- 키워드 기반 최고 좋은거 bm-25알고리즘
- 검색석능 높히는거 **hyde와 reranking**
- **임베딩 모델의 입력의 길이 제한은 존재한다. 그래서 임베딩 모델의 길이를 확인해야한다.**
- LLM은 입출력을 포함한 길이 제한, 임베딩 모델은 넣는거의 길이만 제한
- e5라는 임베딩 모델도 존재, 이것도 대표적으로 한국어 잘하는 모델임, 근데 이건 max 토큰의 길이가 너무 짧다.
- 토큰의 계산은 어덯게하냐? = 그냥 오토토크나이저 불러와서 직접 인코더해서 길이를 재봐라
- 임베딩 모델은 SentenceTransformer을 불러와야함
- 새로운 데이터를 위한 차원을 늘리는 방식으로 학습? = 일반적인 파인튜닝 학습 방법
- 파인튜닝 학습데이터 구성 Simcse 방식으로 데이터를 구성해야한다.
- LLM과 같은 모델들은 내부에 임베딩 구조가 있다. 토큰으로 자르고 그게 임베딩 된다.
