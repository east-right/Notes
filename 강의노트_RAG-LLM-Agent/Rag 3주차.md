## 클로드 api 이미지 인식

- 지금 이미지를 전체 들고오고 모두 적어달라고하면 한번씩 문제가 있다.
- 문서가 복잡하면 테이블 상하의 관계를 잘 인식을 못할 수 도 있다.
- xml를 파이썬 패키지를 통해서 추출이 가능하다. 하지만 클로드로 하는게 좋다.
- 그냥 패키지로 하면 상하의 관계라던가 안의 데이터가 좀 뭉게지는 위험이 있다. 즉 전체적인 pdf의 형식이 뭉개진다. 아니면 테이블 인식이 안되거나.
- 하지만 클로드는 문자가 이상해질수도 조금 뭉게질수도 있지만 전체적인 퀄리티가 좀 높아진다.
- 그래서 클로드에 패키지로 뽑은 글을 이미지랑 같이 넣으면 결과가 좋아진다.

## Agent와 펑션콜링

>  **LLM을 할거면 펑션골링과 react에 있다. 현업에선 제일 엄청엄청 중요하게 다뤄진다. 이게 LLM의 미래 먹거리다.**

- 모든 파라미터의 입력이 들어오면 이제 답변을 하는게 펑션 콜링인가? 잘 모르겠다. 
- 일단 지금 설명은 펑션 콜링의 원리는 사용자가 챗봇한테 각각 맞는 파라미터를 입력하면(질답 과정을 통해) 이제 그때 답을 주고 이때 이 펑션 콜링을 사용하여 agent를 구성이 가능하다.
- 에이전트를 구현하는 방법-> 펑션 콜링, react

> skt 에이전트, LLM orchestrain 뭐뭐뭐 영상 듣고 리뷰

- 저걸 완벽히 봐라 저기 3개 있는건 작동 방식에 따른 구분? 같은거다
- 여기서 부턴 코드는 펑션 콜링 에이전트 이후로 강의
- 펄션콜링 리더보드 -> 버클리 펑션콜링 리드보드
- 요즘 같은 유명한 LLM(gpt, 클로드 물론 오픈소스의 llama, qwen)은 모두 학습되어 나온다.
- 모두 공식 도큐먼트가 있다.
- 요상황에선 이 펑션을 호출해야하한다. 라는 걸 알아야하낟. 펑션 콜링은 기본적으로 함수에 대한 명세를 LLM에게 전달해야한다.
- 펑션 콜링을 사용해서 LLM 에게 답변을 받으면 그 답변 문장을 내어주는게 아니라 어떠한 펑션을 사용해야할지를 답변한다.
- LLM 자체는 함수를 호출할 능력이 없다. 그래서 LLM이 질문에 반응하여 사용하면 좋은 함수(우리가 제시한 함수중)를 반환한다.
- 그러면 우리는 이제 그 함수를 사용해서 나온 결과를 파이썬을 통해서 받고(그 이뉴는 LLM은 함수를 호출할 능력이 업삳.)**그 답을 다 LLM에게 넣어서 최종적인 결과를 받아 본다.**
- 강사님은 행거 펑션 코드를 짜듯이 랭체인을 쓰지 않고 gpt를 직접 호출을 해서 직접 받고 넣고 작업을 그냥 파이프라인을 파이썬으로 짜서 넣는다.
- 랭체인으로도 가능해서 설명하는거지 굳이 사용할 필욘 없다.
- 실제상황에선 도구가 여러개 일 때 어떠한 펑션을 사용해야하냐? -> 그건 LLM이 판단하게 말하는거임
- 펑션콜링 에이전트는 여러개를 줘도 질문에 맞는 펑션을 1개일 수도 있고 여러개일수도 잇지만 그걸 전부 들고오게 가능하다.
- 비전펑션 콜링 -> 이미지를 펑션 콜링 입풋값으로 사용가능하다. 이거 때문에 클로드에게 주면 화면을 캡쳐해서 그건 받아 다음 행동일 해야하는 펑션을 불러와 자동으로 원격 당하는거 처럼 컴퓨터를 움직이게 할 수 있다.
- 앞으로도 funshion calling은 매우 중요해질것이다.

## react vs 평션 콜링

- 펑션 콜링은 cot 과정이 없는 도구 호출 에이전트다.
- 이전에 react 에이전트로 구현되어 있던 많은 프로젝트가 펑션 콜링으로 전환되는 추세이다.
- 모델의 성능이 좋아지면서 cot 없어도 도구 호출이 정확하게 가능한 겅우가 많아짐
- 하지만 반대로 펑션 콜링이 파인튜닝 후에도 잘 동작하지 않는다면 성능을 올리기 위해 다시 cot를 추가하여 react 에이저트로 변경하는것을 고려하기도 한다.
- a에 대한 결과를 찾고 거기서 b를 찾아야하는데 이게 한번에 들어가먄면 문제가 생긴다. 그럴때는 react가 필ㅇ요하다.
- 즉 질문에 대한 결과를 할 때 쿼리를 분리를 해야할때가 있다. react는 이를 해결해주지만 펑션콜링은 cot 기반이라 아니라 이 결과 도출을 제어하기가 되게 좀 어렵다.
- 오픈모델 파인튜닝은 내 도메인에 맞게 시나리오에 맞게 특정 함수를 호출하도록 학습한다.
- 파인튜닝이 가능하다면 펑션 콜링을 권장하지만 생각이 없기에 성능과 속도의 적절한 trade-off 테스트가 필요하다.
