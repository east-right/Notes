## LLM을 이용한 이미지 정보 추출
LLM을 이용해서 이미지 정보를 추출이 가능하다. 대표적으로 클로드 API를 통해서 이미지를 제공하고 Prompt를 작성하면 이미지에 대한 설명 혹은 해석과 같은 원하는 결과를 받아 볼 수 있다.
이 LLM을 통한 이미지 정보 추출은 RAG에 필요한 도큐먼트를 구성할 때 매우 중요하다. XML을 파이썬에서 사용가능한 PDF 전처리 패키지를 사용해서 내용 추출이 가능하지만 이 경우 PDF 내에 있는 테이블과 표 혹은 사진까지는 처리하기 매우 까다롭고 PDF의 전체적인 형식이 뭉게진다.
PDF에서 가장 까다로운 처리는 **다단 형식의  페이지 처리이다.**
![](assets/Pasted%20image%2020250109140525.png)
다단이란 위 그림과 같이 한 PDF 페이지에 반 페이지씩 쌍을 이루어 한 페이지를 구성한다든가 하는 경우를 말한다.  그래서 LLM을 사용하면 이러한 PDF의 형식에 제약을 받지 않고 내용 추출이 가능하다.
보통 반 페이지끼리 한 페이지를 이루는 경우 가운데 부분에 흰부분이 많아 이 부분을 기점으로 페이지를 쪼갠다.
근데 만약 여기서 더 나아가 문단이 한 페이지에 끝나지 않고 다음 페이지까지 이어지는 경우도 존재한다. 이럴때는 **Graph RAG** 라는 걸 이용하면된다.

## Agent와 외부 도구 사용
> 현재 LLM의 발전은 Agent 형식으로 발전하고 있다. 개중 react와 Function calling이 이 부분의 선두 주자 들이다.

LLM 에이전트란 **입력받은 정보를 바탕으로 작업을 수행하거나 결정을 내리는 자율적인 개체**를 의미한다.
개중 가장 자주 사용하고 유명한것이 react와 Function calling이며 [[리뷰_LLM orchestration 기술을 활용한 고객센터 에이전트 개발 사례_SK텔레콤 설용수]]에서 매우 자세하게 확인 가능하다.
### React
> 여기에 React 논문 리뷰한거 연결해라 ㅇㅇ

ReAct(Reasoning + Acting)은 프린스턴 대학교 학자들이 구글 연구원들과 협력하여 개발한 프롬프트 엔지니어링 전략이다.
RaAct는 LLMs(대형 언어 모델)이 인간이 현실에서 행동하는 방식처럼 먼저 문제를 어떻게 풀지 '생각'하고, '행동'을 하는 것을 흉내내는 전략이다.
기본적으로 ReAct는 CoT(이거도 리뷰한 논문이랑 연결해라 ㅇㅇ)를 적극 활용 하는데 **다수의 외부도구를 활용하여 CoT와 비슷한 방법으로 생각 -> 행동 순으로 결과를 도출한다.**
ReAct는 이러한 과정을 하나의 Agent로 관리하여 인간과 유사한 방식으로 작업을 완료한다. 대표적으로 GPT-o1이 잘짜여진 Agent ReAct 모델의 표본이다.

예시 코드를 보면 위와 같이 행동해야 하는 두 가지의 Agent를 제시를 하고 에이전트가 선택되면 제시된 CoT 형식을 따라서 행동 -> 실행 -> 행동 -> 실행을 기록을 하며 진행을 한다.

### Function Calling
Function Calling은 대규모언어모델(LLM)을 외부 툴에 안정적인 연결을 통해 효과적으로 툴을 사용하거나 외부 API와의 상호 작용을 가능하게 합니다.
LLM으로 어떠한 문제를 풀기 위해서 같은 질문이 들어와도 과거의 질문 혹은 질문 주제에 따라 다른 정보를 기반으로 답변을 해야 하는 데, RAG만을 사용하여 답변하기에는 무리인 쿼리들이 종종 있다. 예를 들어 현재 날씨 예보에 기반하여 답변을 해야하는 경우 기상청의 날씨 API를 사용하거나 네이버에 일기예보를 검색하여 나온 정보를 바탕으로 답변을 해야 하는데 이때 Function calling이 사용된다.
![](assets/Pasted%20image%2020250110142951.png)
즉 Function Calling은 질문에 따라 답변에 알맞은 함수를 호출하여 사용자가 원하는 답변을 생성하게 LLM Agent를 만드는 기술을 말한다. 여기서 중요한점은 **LLM은 함수를 실행시키는 기능을 탑재하지 않다. Function Calling은 쿼리가 들어오면 주어진 함수의 정의를 바탕으로 사용하기 알맞은 함수를 찾는 거지 함수를 실행시키는 게 아니다.**
LLM이 함수를 하나 선택하면 그 함수의 result를 받으면 다음 LLM 행동의 답변 생성에 사용된다. Function Calling은 직접짜거나 Langchain으로도 구현가능하고 Open API에서도 제공해준다. 문제에 따라 Function Calling의 결과값이 하나 일 수 있고 두 개 이상일 수 있다. 
이 Function Calling은 비전문제에도 사용 가능한 데 목표를 정해서 클로드에게 화면을 캡쳐해서 보여주면 두 개를 LLM이 보고 Function Calling을 통해 자동으로 원격 마냥 다음 행동을 하는 서비스도 있다. 다음에 한번 봐라 **평션 콜링은 앞으로 매우 중요해질 것 이다.**

### React vs Function Calling
- 펑션 콜링은 CoT 과정이 없는 도구 호출 Agent다.
- React Agent는 CoT 과정이 필수로 들어간다. 모델한테 외부 Agent를 제시하고 생각을 거쳐 올바른 Agent를 들고오게 하는데 React니까(이 내용 틀리면 수정)
- React가 먼저 나온 방식이지만 요즘은 LLM의 성능이 많이 좋아져서 Function Calling으로 많이 넘어가는 추세이다. 즉 CoT 과정이 들어가지 않아도 LLM이 Agent를 잘 선택해 준다는 것 이다.
- 하지만 반대로 Function Calling은 CoT 과정이 없어 답변 생성의 속도가 React 보다 빠를순 있어도 LLM이 모든 문제에 대해 잘 작동한다는 보장이 없어 만약 Agent 선택의 성능이 별로 좋지 않다면 보다 정확도가 높은 React 사용을 고려해야 한다.
- 예를 들어 a함수를 호출하고 b함수를 호출해야 올바른 결과가 나오는 상황에선 이 행동이 한 번에 수행되면 결국 문제가 생긴다. 이러한 문제가 FuntionCalling으로 해결되지 않을 땐 CoT로 해결하는 게 제일 좋은 방법인데 이때 React가 필요한 시점이다.
- 이 오픈 모델에 Function Calling 기술을 잘 해결하게 하기 위해선 이 작업에 대한 파인튜닝이 필수로 필요할 것 이다.
- React와 Function Calling의 선택의 기준은 성능과 속도의 적절한 Trade off 이다.
