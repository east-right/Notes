## RAFT

- Rag 상황을 가정하고 파인튜닝 시키는거 = RAG 파인튜닝
- 실제 RAG 상황을 고려하여 질문에 대한 내용이 존재하지 않아도 검색되어 인풋으로 들어가는 상황이 존재하는데 이러한 상황을 고려하여 네거티브 포지티브 문서 둘 다 학습에 넣어서 사용한다.
- 기본적으로 네거티브 문서 상황을 가정 + CoT prompt를 구성하여 답변학습데이터 생성 => 파인튜닝 형식이다.
- cohere라는 RAFT 방식과 비슷한 **RAG 특화 회사에서 제공하는 모델이 있다.** 이 모델이 RAFT와 비슷한 학습과 답변 생성 방식을 사용한다.
- cohere은 원문 인용을 무조건 강제하고 이로인해 할루시네이션을 방지한다.
- cohere은 RAFT와 답변 방식은 조금 다르다. 사진을 보면 알겠지만 스페셜 토큰들을 적극적으로 사용하며 어느 문석에서 인용되었는지, 답변과 같은 산출물을 스페셜 토큰으로 묶어서 반환한다.
- orion도 존재한다. orion도 본인들만의 특정 prompt 방식을 사용한다.
- 하지만 RAFT 방식의 quote 인용이나 Cohere 방식의 <doc></doc> 방식 같은 원문 강제 인용 보단 조금 별로다.

## 강사님 파인튜닝 코드

- 기계독해 데이터는 찾으면 나옴
- 지금 네커티브 샘플즈를 만드는 코드가 맨 처음 오는데 여기 코드의 가장 핵심은 데이터를 질문/포지티브문서/네거티브문서 로 만드는게 핵심이다.
- 학습 시 데이터를 넣을 때 순서도 중요하다. 만약 포지티브 문서가 항상 맨 처음에 존재하면 모델은 내용이 아니라 이러한 패턴을 학습한다. 그렇기에 데이터를 구성을 할 때 문서의 등장의 순서를 섞어라
- 여기는 기계독해 학습 데이터 셋을 구성하는 2번 째파일이ㅏ. 
- 지금 코드의 초반에는 검색된 문서가 5개인 경우로 학습을 하는데, 이렇게만 구성하면 안된다. 검색된 문서가 4개 이하인 경우도 학습을 하여 학습해야한다
- 여기는 3번째 파일이다.
- 여기서 넓은 질문 = 좋은 질문 이라는 개념이 있다.
- 좁은 질문? 이게 시발 갑자기 무슨 말이냐?
- 넓은 범위의 질문을 만들 때 질문을 생성 할 때 1.인용한 문서, 2. 근거 작성, 3. 예시 제시, 4. 너무 긴 질문은 배제 를 하면서 최대한 넓은 범위의 질문을 생성하게 하는데 사용자가 할만한 질문을 생성
- 강사님은 질문을 주는 데 예시로 이 때 결정이라는 근거를 예시에 작성을 한다. 즉 모델한테 **질문을 생성 할 때** 최대한 문서를 참조하게 만들면서 그 근거를 생각하게 만든다.
- 여기 질문 생성의 핵심은 넓은 질문 + 그리고 다수의 문서를 참조하여 만든 질문
- 넓은 질문이란 -> 포괄적인 질문이란 말이다.
- 4번째는 내가 집중 못하고 넘어감

- 여기서 제일 중요한건 RAG 상황은 질문이 들어오면 무조건 문서를 참조한다는 거다.
- 그리고 gpt4는 실수를 많이 하기에 판단과 같은 안정장치를 넣어주는데 문서에서 질문을 만들어라고 한 다음에 이걸 최종 결과에 true/false 를 출력하게 만들어서 스스로 판단하게 만든다.
- 여기서 문제가 있는게 학습 데이터를 한글로 하면 영어로 질문을 하면 그 성능이 또 떨어진다.
- 그래서 영어로 질문이 들어오는 상황이 존재한다면 영어로도 학습을 시켜야 한다.
- 학습데이터의 핵심은 nagative의 퀄리티가 많은 영향을 미친다.
- 이 nagative는 하등 상관없는 질문 보단, 질문과 언뜻 비슷해보이지만 결과 도출에 도움이 되지 않는 질문들을 넣어야 성능이 매우 좋아진다.
- gpt4로 RAFT 형식으로 데이터를 받는 상황은 생각외로 좀 어려움
