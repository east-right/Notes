## 리랭크

리랭킹: 첫번째 검색이 끝나고 나서 두번째 검색을 한 번 더 해서 순위 조정

-  그래서 첫번째 임베딩 모델 성능보단 두번째 임베딩 모델 성능이 더 좋아야 한다.
- 리랭킹 컨셉에서 두 번째 모델은 기본적으로 첫번째 모델 보다 비용이 비싸고나, 무거운 모델이라 전체 문서에 적용하기 어려운 모델
- 그래서 아래와 같이 진행된다.
  - 첫번째 임베딩 모델: 1000개에서 유사도 top 10
  - 두번째 임베딩 모델: top 10에서 유사도 점수를 재층정해서 순위를 재조정하고 top 5만 남긴다.
- 버트로 임베딩 유사도가 가능함
- 버트로 유사도 검색하는 방식이 존재한다. cros encoder를 검색하면 버트로 인코더 두개 존재 임베딩 기준
- https://www.sbert.net/examples/applications/cross-encoder/README.html
- bi가 기존 방식 cross는 새방식
- RAG에서 cross는 리랭크 상황에서 첫번째 모델로 사용 못함, 왜나면 cross는 모든 문서가 임베딩이 되어 있는 상태여야 하기에, 쿼리가 들어 올 때 마다 임베딩후 유사도 검사를 해야한다.
- 하지만 cross가 bi보다 성능은 일반적으로 높다
- 그래서 리랭크시에 cross 인코더를 두번째 모델로 많이 사용한다.
- bgm-m3는 bi 인코더임
- 리랭커라고 이름 붙혀져 있는 bge-m3는cross 모델임

## 질의 변형

-  사용자의 쿼리는 짧고, 검색문서는 길다
- 그래서 먼저 LLM 한테 쿼리질문을 답변하라고 해서 최대한 검색 문서랑 길이를 비슷하게 맞춘다.
- 그러면 LLM이 준 내용과 검색문서의 내용이나 길이 키워드 들이 비슷하여 서로 검색하기 편할것이다.
- 그게 **hyde**라는 논문의 핵심이다.
