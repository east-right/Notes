## 1. 서비스 브로커란?

### 1-1. 서비스 브로커 정의

**서비스 브로커(Service Broker)**는 개발자(또는 애플리케이션 플랫폼)와 백엔드 서비스(데이터베이스, 메시지 큐 등) 사이에서 중개자 역할을 하는 API 서버입니다.

개발자가 데이터베이스나 캐시 같은 외부 서비스를 사용하려면 직접 인프라를 구축하고, 네트워크를 설정하고, 계정을 생성해야 하는 복잡한 과정을 거쳐야 합니다. 서비스 브로커는 이러한 **인프라 프로비저닝 및 관리의 복잡성을 추상화**하여, 개발자가 간단한 API 호출만으로 원하는 서비스를 즉시 할당받고 애플리케이션에 연결할 수 있게 해줍니다.

### 1-2. 서비스 브로커 구성 요소

서비스 브로커 생태계는 크게 세 가지 요소로 상호작용합니다.

- **플랫폼 (Platform):** 쿠버네티스(Kubernetes), 클라우드 파운드리(Cloud Foundry) 등 개발자가 애플리케이션을 배포하고 실행하는 환경입니다.
    
- **서비스 브로커 (Service Broker):** 플랫폼의 요청을 받아 실제 서비스 인프라를 제어하고 라이프사이클을 관리하는 중개 서버입니다.
    
- **서비스 (Backing Service):** MySQL, Redis, RabbitMQ 등 애플리케이션이 실제로 필요로 하는 외부 데이터 서비스나 백엔드 시스템입니다.

## 2. OSBAPI (Open Service Broker API)

### 2-1. OSBAPI와 설계 철학

**OSBAPI(Open Service Broker API)**는 플랫폼과 서비스 브로커 간의 통신을 표준화한 HTTP API 규격입니다. 원래 Cloud Foundry에서 시작되었으나, 그 유용성을 인정받아 쿠버네티스 등 다양한 플랫폼에서 채택하는 업계 표준이 되었습니다.

**설계 철학:**

- **관심사의 분리(Decoupling):** 플랫폼은 서비스가 어떻게 만들어지는지 알 필요가 없고, 서비스 브로커는 애플리케이션이 어떻게 돌아가는지 알 필요가 없습니다. 오직 '표준 API'로만 소통합니다.
    
- **플랫폼 독립성:** OSBAPI 규격만 맞추면 어떤 클라우드 플랫폼이든, 어떤 백엔드 서비스든 자유롭게 결합할 수 있습니다.
    

### 2-2. OSBAPI 구성 요소 (라이프사이클)

OSBAPI는 서비스의 생명주기를 관리하기 위해 다음 네 가지 핵심 기능을 정의합니다.

- **카탈로그 (Catalog):** 브로커가 제공할 수 있는 서비스의 목록과 각 서비스의 요금제(Plan)를 플랫폼에 알려주는 기능입니다. (예: "MySQL 서비스 제공 가능, 요금제는 Small, Large가 있음")
    
- **프로비저닝 (Provisioning):** 개발자가 특정 서비스를 사용하겠다고 요청하면, 브로커가 실제 자원을 생성하는 단계입니다.
    
    - _Service (서비스 클래스):_ 제공되는 서비스의 종류 (예: AWS RDS MySQL)
        
    - _Service Instance (서비스 인스턴스):_ 실제로 생성되어 할당된 독립적인 리소스 (예: 내 프로젝트 전용으로 띄워진 10GB MySQL DB)
        
- **바인딩 (Binding):** 생성된 서비스 인스턴스에 애플리케이션이 접근할 수 있도록 자격 증명(접속 URL, ID, Password 등)을 발급하는 과정입니다.
    
- **삭제 관련 (Unbinding & Deprovisioning):** 사용이 끝난 서비스와의 연결을 끊고(Unbinding), 할당되었던 리소스를 회수 및 삭제(Deprovisioning)하여 인프라를 정리합니다.

## 3. 서비스 카탈로그

### 3-1. 서비스 카탈로그 정의

**서비스 카탈로그(Service Catalog)**는 서비스 브로커가 제공할 수 있는 **'메뉴판'**입니다. 브로커가 연동할 수 있는 모든 서비스 클래스와 각각의 플랜(성능, 용량, 가격 등에 따른 등급)에 대한 메타데이터가 체계적으로 정리되어 있습니다. 개발자는 이 카탈로그를 보고 자신의 애플리케이션에 필요한 스펙의 서비스를 선택합니다.

### 3-2. 쿠버네티스 서비스 카탈로그 (Kubernetes Service Catalog)

쿠버네티스 환경에서 외부 서비스를 마치 쿠버네티스 네이티브 리소스처럼 다루기 위해 도입된 확장 API(Extension API)입니다. 외부의 다양한 OSBAPI 호환 서비스 브로커들을 쿠버네티스 클러스터에 등록하면, 쿠버네티스 서비스 카탈로그가 이를 취합하여 사용자에게 하나의 통합된 리스트(메뉴판)로 보여줍니다. 이를 통해 개발자는 쿠버네티스의 `kubectl` 명령어만으로도 외부 클라우드의 데이터베이스를 쉽게 프로비저닝하고 파드(Pod)에 연동할 수 있습니다.

## 4. 클라우드 서비스 브로커 (Cloud Service Broker)

### 4-1. 클라우드 서비스 브로커란?

퍼블릭 클라우드(AWS, GCP, Azure 등)에서 제공하는 다양한 매니지드 서비스(RDS, Cloud SQL, S3 등)를 OSBAPI 규격에 맞게 래핑(Wrapping)하여 제공하는 특정 형태의 서비스 브로커입니다. 기업 내 플랫폼 환경(예: 온프레미스 쿠버네티스)에서 퍼블릭 클라우드의 자원을 표준화된 방식으로 끌어와 사용할 때 핵심적인 역할을 합니다.

### 4-2. 클라우드 서비스 구성 요소

- **클라우드 프로바이더 API:** 실제 인프라 자원을 생성하는 주체입니다. (예: AWS API, GCP API)
    
- **IaC(Infrastructure as Code) 엔진:** 최근의 클라우드 서비스 브로커들은 테라폼(Terraform)과 같은 IaC 도구를 내장하여, OSBAPI 요청이 들어오면 이를 테라폼 코드로 변환해 클라우드 자원을 배포하는 방식을 많이 사용합니다.
    
- **브로커 애플리케이션:** OSBAPI 규격을 수신하고, 이를 IaC 엔진이나 클라우드 API 호출로 변환하는 비즈니스 로직을 담당합니다.
    

### 4-3. 클라우드 서비스 카탈로그

클라우드 서비스 브로커가 제공하는 메뉴판으로, 퍼블릭 클라우드의 복잡한 서비스들을 조직의 정책에 맞게 정제하여 보여줍니다. 예를 들어, 개발자에게 AWS의 수많은 옵션을 모두 노출하는 대신 "Standard DB (AWS RDS db.t3.micro)", "Production DB (AWS RDS db.m5.large)"와 같이 표준화되고 승인된 클라우드 서비스 목록만 카탈로그에 담아 제공함으로써 거버넌스를 유지하고 복잡성을 줄입니다.
