## 오라클 파티션이란?
오라클 파티션(PARTITION)은 테이블이나 인덱스를 논리적 개념으론 하나의 테이블 이지만 **내부적으로 하나의 세그먼트로 놔두지 않고 여러 세그먼트로 분리해 저장하는 방식이다.**

예를 들어, 수백만 건 이상의 데이터가 있는 큰 테이블을 파티션으로 나누면, 특정 데이터를 빠르게 조회하고 관리하기가 쉬워진다.

## 파티션의 장점
- 서치 속도 증가
	- 특정 테이블을 탐색할 때 where절을 쓰면 해당 데이터가 존재하는 파티션만 서치하면 된다.
		>랜덤 io를 하면 해당 블록의 테이블을 읽는데 왜 필요함?
		>	모든 조건이 인덱스를 타지 않는다”는 데 있다.
		>	WHERE 절이 **범위 조건** 또는 **대량의 행을 반환하는 조건**이면?
		>	인덱스는 결국 **ROWID를 너무 많이 생성**하게 됨  
			    → 이것이 “인덱스 스캔이라도 사실상 풀스캔 수준의 I/O”로 바뀜
		그리고 결정적으로 index 테이블도 너무 클수 있기에 파티션을 나눈다.
- DML 성능 향상
	- 특정 파티션에만 DML이 가능해 기본적으로 성능 업
- **관리 용이성 (운영에서 엄청 중요)**
	- 오래된 데이터 파티션 드롭으로 손쉽게 삭제 가능
	- 파티션별 이동 압축 가능
	- 파티션별 import export 가능

## 파티션 종류
- 파티션의 종류는 총 3가지로 나뉜다. range, list, hash
- range 파티션
	- 범위를 기준으로 테이블을 나눈다.
	- 대표적으로 날짜(기간), 수치 등이다.
	- 관리가 쉽지만 특정 범위 즉 특정 파티션에 데이터가 몰릴 위험 
	- 파티션 프루닝이 잘된다.
> 	파티션 프루닝이란?
		하드 파싱이나 실행시점에서 sql조건절을 분석해서 읽지 않아도 되는 파티션 세그먼트를 엑세스 대상에서 제외시키는 기능 -> 자세한 파티션 프루닝은 [여기](obsidian://open?vault=Obsidian_note&file=Area_of_responsibility%2FDB%2F%ED%8C%8C%ED%8B%B0%EC%85%98%20%ED%94%84%EB%A3%A8%EB%8B%9D)
- List
	- 명확한 값을 기준으로 나눔
	- 대표적으로 지역, 상태값 등
	- 그룹별 io관리가 완벽히 분리 되어 있다.
	- 값이 너무 다양하면 파티션 종류가 늘어난다.
- hash 
	- 헤시 알고리즘 기반 균등 분포 파티셔닝
	- 파티션에 데이터 불균형 문제를 해결
	- 하지만 데이터가 퍼져있기에 파티션 프루닝이 불가하여 cost가 높아진다.
	- 균등 분포가 필요한 OLTP성 테이블이 많이 사용된다.
- 보통 range+hash 방식을 많이 사용한다.
	- 시간기반으로 range+ 그 안헤서 hash를 사용하여 서브 파티션 생성(물론 대용량일 때)

## 파티션 관리
- 파티션의 크기들을 최대한 균등해야한다.
- 파티션이 불균형하면 특정 파티션의 성능이 떨어지게되고 인덱스, 통계(obs), 백업 성능까지 모두 떨어지게 된다.
- 파티션 테이블에선 최대한 로컬 인덱스를 사용하면서 파티션 프루닝이 잘 일어나게 관리하여야 한다.
