## 파티션 프루닝이란?
- 프루닝이란 컴퓨팅에서 많이 쓰는 용어로 보통 가지치기라고 한다.
- 프루닝은 최대한 불필요한 부분을 삭제하면서 불필요한 작업을 최대한 삭제하는 작업니다.
- 그런 의미에서 파티션 프루닝이란 **하드 파싱이나 쿼리 실행시점에서 sql문을 분석하여 조건절에 따라 굳이 읽지 않아도 되는 파티션 세그먼트(파티션 테이블, 파티션 인덱스)를 엑세스 대상에서 제외하는 작업을 말한다.**

## 로컬인덱스와 글로벌 인덱스
- 로컬인덱스
	- 각 파티션별로 인덱스가 존재하는 인덱스
	- 1:1 대응관계
	- 관리가 용이하고 테이블 파티션 구성을 변경하더라도 빠르고 안전하게 서비스 중단없이 추가 가능
- 글로벌 인덱스
	- 하나의 인덱스 파티션이 여러개의 파티션 테이블을 가지고 있을 때를 말한다.
	- 1:n 관계, 그리고 **보통은 테이블이 파티션 되도 인덱스는 파티션 되지 않은 걸 생각함**
	- 관리가 어렵다. 만약 테이블 파티션 구성이 바뀌면 삭제하고 다시 생성해야한다.
	- 대신 전반적인 파티션끼리의 관리가 가능
	- oltp에서 많이 사용
		- 이 부분 조금 동의를 못하겠는게 단건 조회는 몰라도 2~3건 조회하는 oltp에선 오히려 나쁠거 같은데
		- 아마 업데이터가 많이 일어나는 배치에서 못쓴다고 이리 말한듯
	- 주로 테이블 파티션키와 인덱스 파티션키가 다른 경우 생성하면 좋다
		- 즉 인덱스는 deptno로 짜여있는데 파티션은 range로 생성하기 위해 date로 될때 좋다


## prefixed와 Nonprefixed
- prefixed
	- 인덱스 파티션 키 컬럼이 인덱스 키 컬럼 왼쪽 선두에 위치, 즉 파티션 키와 인덱스 키가 같을 때
- Noneprefixed
	- 인덱스 파티션 키 컬럼이 인덱스 키 컬럼 왼쪽 선두에 위치하지 않는다. 파티션 키가 인덱스 컬럼에 아예 속하지 않을 때도 여기에 속한다.
	- 즉 인덱스 선두컬럼 기준으로 파티션을 나누지 않고 다른 컬럼일때 발생

이렇게 파티션 인덱스는 총 4가지가 존재한다.
- 로컬 인덱스 + prefixed
	- 각각 파티션에 인덱스가 존재하고 분리된 기준 컬럼이 같다.
- 글로벌 인덱스 + prefixed
	- 글로벌 인덱스 인데 테이블 파티션이 나눠질 때 인덱스 키값과 같은 컬럼으로 나눠짐
- 로컬 인덱스+Nonprefixed
	- 로컬인데 나눠질 때 같은 키값을 기준으로 나눠지지 않음
- 글로벌 인덱스 + nonprefixed
	- 아무것도 아님 이러면 ㅋㅋ 그냥 글로벌 인덱스 인거임
	- 보통 nonprefixed 일때 엄청난 대용량 테이블이면 글로벌 사용하는데 이 경우가 많을듯
