#DB #dba #oracle 
![](assets/Pasted%20image%2020251130115224.png)
- 데이터 베이스의 저장 관점의 논리적 단위 중 하나이다.
- 논리적 단위와 물리적 단위로 구분 되는데 이게 저 오브젝트랑 헷갈렸다. 
- 난 이게 저장 위치 이니깐 데이터 베이스의 물리적 개념인줄 알았다.
- 그게 아니라 오브젝트의 논리적 개념은 
---
- **DataBlock(oracle block)**
	- 오라클에서의 가장 기초가 되고 작은 저장 단위이자 i/o가 이루어질 때 가장 최소 단위
	- Row, Index Entry, Undo 등이 모두 Block 안에 저장됨.
	- Block 내부 구조: Header + Table Directory + Row Directory + Row Data.
	- 보통 8kb

- **Extent**
	- 연속된 블록의 묶음 보통 8~64 block 끼리 묶음
	- 오라클 공간 할당의 최소 단위
		- 테이블이 생성이 되면 익스텐드 공간이 할당이되고 데이터가 많아지면 자동으로 추가 할당한다.

- **Segment**
	- **DB내의 생성되는 실제로 저장이되는 객체(테이블, 인덱스 등등)들이 저장될때 세그먼트 단위로 저장한다.**
	- 여러개의 Extent가 모여서 구성된다.
	- 즉 우리가 테이블이나 인덱스 파티션을 나누면 세그먼트 공간에 저장이 된다.

- **Datafile**
	- 실제로 데이터가 저장되는 물리파일
	- 물리적으로 디스크에 저장된 블락들을 파일형식으로 관리한다.

- **Table Space**
	- **여러 Segment를 논리적으로 나누고 묶을 때 사용되는 상위 저장 구조**
	- 이 단위로 Datafile를 분류하여 저장한다.
	- 실제로 데이터 저장할때 테이블 스페이스를 기준으로 데이터 저장 위치를 나눈다.
	- 인덱스 스페이스, 유저 데이터 테이블 스페이스, 상품 데이터 테이블 스페이스 등등
	- 이렇게 나누어야 나중에 힌트를 주거나 해서 목적에 따라 서치 횟루를 낮출수 있다.
		- USERS
		- SYSAUX
		- SYSTEM
		- TEMP
		- UNDO 등이 기본적으로 생성된다.
