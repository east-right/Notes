#온톨로지 #graphdb #owl #rdb
 - 팔란티어는 모든 법 집행 관련 데이터를 하나의 데이터로 통합하는 엔터프라이즈 레이크 하우스 제공의 유일한 업체였다.
 - 사용자가 목적이 명확하지 않아도 데이터 속에서 의미있는 연결고리를 제시한다.
 - 온톨로지의 핵심은 객체, 속성, 라인이다.
	 - 객체
		 - 현실 세계의 대상이나 사건
			 - 사람이름
			 - 회사
			 - 은행계좌
	 - 속성
		 - 객처의 특징을 정의
			 - 객체: 사람
			 - 속성: 이름, 전화번호, 계좌번호
	 - 링크
		 - 객체 사이의 관계를 정의
			 - 사람과 은행계좌의 객체 라인 -> '소유주' 라는 링크 정의
 - 개체 식별
	 - 서로 다른 데이터의 출처에도 동일한 대상을 가리키는 기록을 찾아 연결
	 - ai와 ML 그리고 퍼지 매칭 기법 사용
>[!퍼지 매칭]
문자열 간의 거리를 기반으로 유의어를 찾는 알고리즘 -> 근접 문자열 매칭
- 연결망 분석
	- 네크워크 분석이랑 동의어
		- 연결 중심점
		- 근접 중심점
		- 고유벡터 중심점
- 팔란티어의 온톨로지 시스템은 총 3가지 계층을 핵심으로 한다.
	- 시멘틱 레이어
		- 이 계층에선 '명사'에 해당하는 것들을 정의한다.
		- 현실 세계의 공장, 장비, 고객과 같은 대상을 컴퓨터가 이해할 수 있는 객체로 지정
		- 각 객체의 속성을 집어넣는다.(공장 이름,위치, 장비이름,사용처, 고객이름 등)
		- 각 객체의 링크를 연결한다.
	- 키네틱 레이어
		- 이 계층에선 '동사'에 해당하는 것들을 정의한다.
		- 실제로 수행하는 시스템 내부에서 작동하는 사업 논리를 컴퓨터가 이해하고 실행할 수 있는 형태로 전환
		- 조회(select), 분석 결과 바탕 재작성(update)
	- 다이나믹 레이어
		- 이 계층은 'what if' 와 같은 가상 시나리오를 탐색하는 기능 담당
		- 시뮬레이션 기능과 의사결정 과정을 따로 기록하여 전략 수립과 실제운영을 실시간으로 연결한다.
		- 그래서 미리 예측하고 시험해볼 수 있게 된다.
- 두 graphdb
	- neo4j
		- 풍부한 기술문서와 활발한 커뮤니티
		- cyper라는 언어는 쉽고 구조적으로 직관적임
		- 일반적인 그래프 탐색이나 세단계 이내의 관계를 찾아낼때 안정적인 성능
		- 개인화 추천 엔진, 고객의 정보 종합 엔진 같은 넓은 범위의 일반적인 탐색에 특화
	- tiger graph
		- 대규모 병렬처리 구조 기반으로 만들어짐
		- sql과 비슷한 언어인 gsql로 사용
		- 심층 분석에 특화
	- 두 그래프디비를 선택하는 기준은 뭐가 더 빠르냐를 넘어선, '어떠한 종류의 질문이 많이 들어오고, 그 질문에 더 안정적이고 정확하고 빠르게 탐색이 가능한가?'를 생각해야한다.
		- 적절한 etl전략과 인덱싱 모델링도 말하는 거 보면 이거 디비 공부하길 잘한듯
- 데이터 가상화 
	- 계층 오픈소스
		- 트리노(trino)
			- 여러곳에 퍼져 있는 데이터를 sql로 검색하게 해줌
			- 분산 sql 검색 엔진
			- rdbms, storage 같은 저장소가 아니라 컴퓨팅 계층을 나누어 각 rdbms, storage, nosql를 연결하고 sql 문으로 한번에 서로 다른 저장방식이라도 분산 병렬로 들고온다.
			- 잘 모르겠음 
			- 요놈은 엔진 같은거
		- 데노도(denodo)
			- 데이터 통합, 권한 관리, 데이터 목록을 하나의 플랙폼으로 통합하여 제공하는 데이터 가상화 툴
			- 요놈은 엔진을 사용한 완성된 자동차 같은거, 그니까 잡다하고 중요한거 다 붙은
	- 쿼리 푸시다운
	- 데이터 캐싱 전략
- 시멘틱 레이어 구성 방법
	- 직접 분석하여 구성하기
		- 데이터 분석해서 구성하면됨
	- lookml을 이용하여 구성하기
		- 시멘틱 모델링 언어
		- 데이터 베이스와 실제 작업자의 추상화 계층을 만들어 sql 몰라도 분석가능하게함
		- sql알고 분석할줄 알면 메타데이터 정의 관리 용으로 사용
- typedb
	- 논리 규칙에 기반한 자체 추론 엔진 존재
	- 개체 -관계에 기반한 강력한 하이퍼그래프 모델
	- 데이터 베이스에 명시적으로 저장하지 않은 관계도 typedb로 불러오면 얘가 관계를 추론한다.
- 오픈메타 데이터
	- 타입디비가 엔진이라면(뭔 비유가 죄다 엔진이냐) 오픈메타 데이터는 계기판이자 관제탑
	- 데이터 품질, 거버넌스, 검색, 협업등 기능을 하나로 통합한 오픈소스
	- 메타데이터를 그래프 모델로 관리하는 중앙 메타데이터 저장소
- dbt, airflow
- 상용기술 경로 neo4j, denodo, dbt/looker 조합을 여기선 메인으로 설명하고 있다.
- 오픈소스 경로 typedb와 오픈메타데이터
