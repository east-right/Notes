둘 다 행렬곱을 구하는 numpy의 함수이나 두 개의 결과가 다르게 나오는 경우가 종종있다. np.matmul은 파이썬의 @과 같은 효과를 낸다. 

### 같은 결과를 내는 경우

**1. 1차원 \* 1차원 (내적 연산)**

**2. 2차원 \* 2차원 (2차원 행렬곱)**

**3. 2차원 \* 1차원 or 1차원 \* 2차원 (행렬 \* 벡터곱 연산)**

```python
import numpy as np
a = np.array([[1,2],[2,4]])
b = np.array([[1,0],[2,1]])
c = np.array([2,1])

print(a@b)
print(np.dot(a,b))
print(np.matmul(a,b))
>>>[[ 5  2][10  4]]
>>>[[ 5  2][10  4]]
>>>[[ 5  2][10  4]]

print(a@c)
print(np.dot(a,c))
print(np.matmul(a,c))
>>>[4 8]
>>>[4 8]
>>>[4 8]
```

### np.matmul과 np.dot이 다른 경우 1 : 배열과 스칼라의 곱

두 함수의 첫 번째 차이는 np.dot은 np.multiply에서 제공하는 스칼라와 배열의 곱을 지원하지만 **np.matmul 함수는 스칼라와 배열의 곱에서 오류가 발생**

### np.matmul과 np.dot이 다른 경우 2 : 3차원 이상 다차원 배열곱

이 부분이 두 함수의 가장 큰 차이점인데, 3차원 이상의 다차원 배열에서 연산을 수행하는 방식이 다르다는 점이다.

차이를 요약하면 

- np.dot(a,b)은 a의 마지막 axis와 b의 마지막에서 두 번째 axis끼리 곱한 결과를 반영
- np.matnul(a,b)은 a의 마지막 두 axis 차원이 (n,k), b의 마지막 두 axis 차원이 (k,m)일 때, 이 사이에서만 곱하여 (n,m) 차원이 되도록 반영

![img](https://blog.kakaocdn.net/dn/cmbh8k/btrrchVEMm0/3DZGUX4hbAFcpt8RQL4wB0/img.jpg)

위 의 사진처럼 계산된다. np.dot은 2 차원 배열끼리 합성곱을 하면 우리가 아는 합성곱 처럼 진행이 되지만, 3차원 이상의 행렬이 들어 갔을 때 계산 방식이 dot은 우리가 아는 방식과 다르게 진행이 된다.

**dot과 matmul의 3 차원 이상의 행렬곱 계산**

- dot을 사용하여 곱하면 첫 번째 차원은 `[[적녹, 적노], [적보, 적분]]`으로 곱이 이루어 지고 두 번째 차원은 `[[청녹, 청노],[ 청녹, 청분]]` 으로 곱해진다.
- matmul은 합성곱을 진행하면 우리가 아는 정석 방식으로 진행이 된다. 첫 번째 차원은 `[[적녹, 적노],[ 청녹, 청노]]` 두 번째 차원은 `[[적보],[적분, 청보, 청분]]` 으로 곱해진다.

위에서 설명한걸 본인식으로 말하면 dot은 a를 기준으로 합성곱을 진행해서 b를 들고 오는거고 matmul은 b를 기준으로 a에 대입 시킨다는 느낌으로 이해 했다.

그래서 차이점을 정리하자면

**np.dot**

- **1차원 배열(벡터) 간**: 두 벡터의 내적(스칼라)을 계산
- **2차원 배열(행렬) 간**: 표준 행렬 곱셈을 수행
- **N차원 배열(N>2) 포함 시**: 배열을 1차원으로 평탄화한 후 내적을 계산하거나, 가능한 경우 마지막 두 축에 대해 행렬 곱셈을 수행합니다.
- **간단한 벡터 연산에 주로 사용되며 단일 뉴런 혹은 2차원 이하 출력 계산에서 입력 벡터와 가중치 벡터의 내적을 구할 때 사용한다.**

**np.matmul**

- **2차원 배열(행렬) 간**: 표준 행렬 곱셈을 수행
- **N차원 배열(N>2) 간**: 마지막 두 축을 행렬로 간주하고, 앞의 축들에 대해 배치(batch) 행렬 곱셈을 수행
- **스칼라 또는 1차원 배열**: 허용되지 않으며 오류를 발생
- **신경망의 배치 연산에 사용되며 다층 퍼셉트론과 같은 고차원 배열의 입력 데이터의 배치와 가중치 행렬의 곱을 계산할 때 적절하다.**

그래서 matmul은 선형대수의 행렬 곱셈 규칙을 엄격히 따르는 합성곱 함수이기에 마지막 두 축에 대해 행렬 곱셈을 수행하고 앞의 축들에 대해 배치 연산을 적용하기에 일관성 있고 예측 가능한 결과를 제공하는데 이는 텐서 연산을 시행하는 AI 계산에 올바르다.

### dot의 평탄화

dot은 같은 행렬곱이라도 벡터의 내적값을 계산하는 함수이다. 즉 **두 벡터을 곱하는게 목적이 아닌 두 벡터의 유사도를 구하는게 주 목적이다.** 보통 벡터는 2차원 행렬을 띄기 때문에 2차원 * 2차원 내적의 값을 구하는 방식이 선형대수의 행렬곱과 같은거지만 3 차원으로 넘어가면 **dot의 평탄화 후 곱하는 방식** 때문에 차이가 난다.

평탄화의 이유

- 호환성과 일반성의 문제: dot은 다양한 차원의 배열에 대해 일반적인 내적 연산을 제공하기 위해 설계되었다. 배열의 차원이 맞지 않을 때 dot은 자동으로 배열을 1차원으로 평탄화 하여 내적 계산을 진행하다.
- 역사적으로 초기 numpy는 설계 시점에서 벡터와 행렬 연산에 초점을 맞추었기 때문에, 거차원 배열에 대한 명확한 연산 규칙이 없었다. 이를 보완하기 위해 배열을 평탄화하여 연산하는 방식을 도입

이러한 이유로 dot은 두 벡터의 내적을 구할 때에만 적절한 방식이다.
