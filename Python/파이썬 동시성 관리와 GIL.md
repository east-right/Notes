## 프로세스와 스레드
> 프로세스란 실행 중에 있는 프로그램을 의미한다. 스케줄리의 대상이 되는 작업과 같은 의미로 쓰인다. 프로세스 내부에는 최소 하나의 스레드를 가지고 있고, 실제로는 스레드 단위로 스케줄링을 한다.

- 프로새스= 프로그램일까? 그건 아니다. 
	- 프로그램-> 파일이 저장장치(하드, SSD)에 저장만 되어있으면 프로그램
	- 프로세스 -> 파일이 저장장치에서 메모리에 올라오는 순간 프로세스
- 즉 프로그램은 아직 실행되지 않은 상태를 의미한다. 그 파일이 이제 실행되는 순간 프로세스로 바뀐다.
- OS가 프로그램에 독립적인 메모리 공간을 할당해서 거기 올라가있어야 결국 "실행됨"이라고 볼 수 있다.

### 동시에 프로세스를 실행시키는법
- 단편적으론 불가능 하다. 뭐 vscode, 크롬, 옵시디언을 전부 실행 시키는 중인데 이건 동시에 실행되는게 아니라 여러개의 프로세스가 동시에 실행되는 것 처럼 보이게 하는 것 이다.
- 하나의 프로세스는 하나의 프로세서(CPU)에서 실행할 수 있다.
- 동시에 실행되게 보이는 이유는 OS가 정말 빠른 속도로 메모리 할당 즉 실행할 프로세스를 교체하기 때문이다.
- 즉 프로세서가 1개만 하나의 프로세스만 n개면 n개 실행이 가능하다는 이야기 이다.
### 프로세스의 상태
![](assets/Pasted%20image%2020260422185132.png)
- 프로세스의 상태는 `Create Ready`, `suspended ready`, `Running`, `Suspended blocked`, `asleep`, `terminated` 로 총 7가지로 나타낼 수 있다.

**created state**
![](assets/Pasted%20image%2020260422185437.png)
- 프로세스가 실행이 시작되는 단계
- 가용 메모리 공간의 유무에 따라 메모리가 할당되면 `Ready`로 메모리가 부족하면 `suspended ready`로

**Ready state**
![](assets/Pasted%20image%2020260422185723.png)
- 프로세서(cpu) 할당을 제외한 모든 자원(메모리)을 할당 받은 상태를 의미 -> 즉 메모리에는 올라옴
- 언제든지 실행이 가능한 상태로 프로세서 할당까지 이루어 지면 비로소 시작
- 시작이 되면 Running state로 가게되면 이를 dispatch라고 한다.

**Running state**, **Asleep(blocked) State**
![](assets/Pasted%20image%2020260422185915.png)
- 필요자원 모두를 할당 받아 실행중이 상태
- 가장 유의깊게 봐야하는건 프로세스를 할당받아 있는 상태라는 걸 알아야한다.
- 이 `Running` 상태를 빠져나가는 방법은 두 가지 이다.
	- Ready 상태로 변경
		- 프로세서의 스케줄링 우선순위 등 프로세서 할당을 반납 후 다시 ready로 대기
		- 이를 preemption
	- Asleep 상태로 변경
		- 프로세서 자원 외 다른 자원을 기다리는 상태
		- 대표적인 예로 I/O 자원을 할당 받기 위한 상태, 즉 디비에서 데이터 꺼내올 때 즉 피지컬리드가 팔요해서 물리 디스크에 가서 들고 올때
		- 이땐 프로세서가 저거 완료될때 까진 할거 없으니 잠시 주고 오는것
	- 이 Asleep은 중요한게 있는데 I/O가 끝나도 Running으로 바로가지 않고 ready로 가서 기다리는데 이를 wake up 이라고 한다.

**Suspended State**
![](assets/Pasted%20image%2020260422190420.png)
- 메모리를 할당 받지 못한, 혹은 빼앗긴 상태
	- Suspended Ready
		- 다른 자원은 할당 받았지만 프로세서와 메모리를 할당 받지 못한 상태
	- Suspended Blocked
		- 프로세스, 메모리, 기타 자원 모두 할당받지 못한 상태
- 어떠한 작업을 완료하고 running에 가야하는데 하는 작업이 많아 메모리를 강제로 빼앗기면 이제 하드로 내려가서 저장하는데 이를 빼앗기기전 상태를 memory image로 저장하고 swap device로 부른다.

**Terminated / Zombie State**
- 프로세스 수행이 끝난 상태
- 모든 자원을 반남하고 커널내의 PCB라는 정보만 남긴다.

## 프로세스의 구성
- PCB라는 모든 프로세스가 끝나면 남기는 찌거기가 존재한다. 아래와 같은 종류가 존재한다.
	- PID(Process ID)
		- 프로세스를 식별하기 위한 부여하는 번호
	- 프로세스 상태
		- Ready인지 Running인지 suspended인지 상태를 말함
	- 프로그램 카운터
		- CPU가 다음으로 실행할 명령어를 가리니는 값, 하나만 처리가능한 CPU가 이번꺼 끝내고 다음거 할거 지정
	- 스케쥴링 우선순위
		- 프로세스 우선순의 지정 즉 프로그램 카운트 매김
	- 권한
	- 프로세스의 부모 자식
		- 최소 생성되는 init 제외 모든 프로세스의 PPID(부모 프로세스)를 복제하여 생성
		- 부모/자식 관계 저장
	- 프로세스 메모리 주소
		- 프로세스에 할당되어 메모리 위치
	- Excute Context
		- 프로세스가 실행상태에서 마지막으로 실행한 프로세서의 레지스터 내용저장
		- 즉 이거를 가지고 프로세스가 CPU에서 내려가고 다시 올라와도 중단되지 않고 연속적으로 실행 되는것 처럼 보이게 만듬

## 프로세스의 데이터와 명령어가 있는 메모리 구성
![](assets/Pasted%20image%2020260424155305.png)
- Text(Code) 영역
	- 사용자가 작성한 프로그램 함수들의 코드가 CPU에서 수행할 수 있는 기계어 명령 형태로 변환되어 저장되는 공간
	- 컴파일 시점에서 결정 되며 코드를 바꿀 수 없도록 Read-only로 되어 있다.
- Data 영역
	- Global(전역) 변수 또는 static 변수 등 프로그램이 사용하는 데이터를 저장하는 공간
	- 전역 변수 혹은 static한 값을 참조한 컴파일이 완료되면 Data 영역의 주소 값을 가리키도록 바뀌는데, 그것을 고려하여 Read-Write로 되어 있다.
	- 이거 이해할려면 그 Python의 변수가 값을 가리키는 주소값 출력 보면됨, 결국 값 출력=메모리 주소에 있는 값 보여주기라는걸 알아야함
- Stack 영역
	- 호출된 함수의 수행을 끝내고 복귀할 주소 및 데이터를 임시로 저장하는 공간
	- 이 영역은 함수의 호출시 기록하고 함수가 끝나면 사라지는 발화성 메모리 공간임
	- 즉 함수 안의 변수들 보면 지정해도 돌아가고 return에 지정된 값이 아니면 그 함수 안의 값을 못보잖아?? 그거임 def 안의 변수들은 stack에 저장되기 때문임
	- return에 있는 값도 결국 마찬가진데 근데 보통 함수 불러오고 값 저장 할려면 `a=def()`로 값 저장 하잖아? 그래서 return 은 원래는 static인데 저렇게 해서 data 영역으로 불러가는 컴파일이 있으니 return 은 data에 가는거
- heap 영역
	- 프로그래머가 필요할 때마가 사용하는 메모리 영역, 런타임 시점에서 결정 된다.
	- java 같은 경우 객체가 heap에 생성되고 **GC(Garbage Collection)** 에 의해서 정리됨

- 프로세스는 위와 같은 메모리로 구성, 메모리를 받으면 받은 메모리 내에서 위와 같은 영역으로 쪼갠다.
- 요즘은 하나의 프로세스 가지고 실행하기에는 벅찬 상황이 많음 -> 한 프로그램을 처리하기 위해 여러 프로세스를 활용하고 싶음
- 하지만 메모리 안정성 때문에 각 프로세스는 자신에게 할당된 메모리 내의 정보만 접근가능 -> 그러면 메모리를 공유하기 위해 프로세스 내에 여러 작업을 하게 하면 되지 않나? -> **스레드의 등장**

## 스레드란?
- 스레드란 실이란 의미다.

> 스레드는 어떠한 프로그램 내에서, 특히 프로세스 내에서 실행되는 흐름의 단위를 말한다. 
> 
> 일반적으로 한 프로그램은 하나의 스레드를 가지고 있지만, 프로그램 환경에 따라 둘 이상의 스레드를 동시에 실행할 수 있다. 
> 
> 이러한 방식을 **멀티스레드** 라고 한다.

- 스레드란 프로세스 내에서 실제로 작업을 수행하는 주체이다. -> 이걸 하나의 작업 흐름 단위로 본다.
- 프로세스의 제어 부분을 스레드가 담당하며, 코드의 절차 수행을 스레드가 한다.
- 즉 프로세스가 움직이고 총쏘는 작업을 하면, 움직임 스레드 -> 총 스래드 -> 움직임 스레드 이렇게 필요한거다(이건 멀티스레드)
- 알아야 할건 **멀티 프로세스와 멀티 스레드의 차이다.**
- 이 문제가 동시성 관리와 GIL에 대해 이해하는 첫 번째 이다.

## 프로세스와 스레드의 차이
![](assets/Pasted%20image%2020260424164233.png)
- 프로세스는 OS 위에서 각각 별도의 메모리 영역을 할당 받고 프로세스의 메모리끼리 서로 자원을 공유하지 않는다.
- 각각의 프로세스는 독립적이고 process1에서 돌아간 변수가 process2에 갈려면 별도의 통신이 필요
![](assets/Pasted%20image%2020260424164501.png)
- 스레드는 stack만 따로 할당 받고 나머지 프로세스 안의 영역은 공유한다.
	- stack 즉 함수의 변수들은 공유 안한다. 한 프로세스에 여러 같은 이름의 여러 변수가 사용되도 안꼬이는 이유
- 각각의 장단점이 조재한다.
	- 멀티프로세스
		- 장점: 모든 프로세스가 독립적이기에 하나에 문제가 발생해도 다른쪽은 영향을 안받아 안정적
		- 단점: 많은 자원을 필요로 하고 통신까지 필요함
	- 멀티스레드
		- 장점: 특정 자원을 공유하기에 비용이 감소
		- 단점: 자원을 공유하기에 공유자원에 대한 접근 권한 관리, 디버깅 등 (그 디비 락,래치 생각하면됨)

## GIL(Global Interpreter Lock)
![](assets/Pasted%20image%2020260424211338.png)
- 간단하게 말하자면 멀티스레드의 메모리 뮤텍스(락/레치)같은 거라고 생각하면 된다.
- 오라클의 버퍼풀 레치와 같이 어떠한 것이(파이썬: 스레드, db: 인스턴스)가 메모리를 공유하는데 한명이 들고 가서 쓰고 있는데 다른 한명이 들어와 값을 변경해 버리면 이건 대형 사고다.
- 즉 멀티스레드 환경에서 여러 스레드가 한번에 같은 메모리의 주소를 참조하다가 값에 대한 변경이 일어나면 갖가지 오류를 발생 시킨다.
	- 대표적으로 GC라는게 존재하는데 파이썬은 메모리 관리를 위해 참조 계수(refernce count)라는 방식을 이용해 객체 메모리를 관리한다.(이 메모리 주소의 값을 가지고 있는 오브젝트)
	- 모든 객체는 이 참조 계수가 1이상이면 메모리에 값이 존재하고 0이 되는 순간 GC가 가용 메모리 확보를 위해 해당 메모리를 삭제 시켜 버린다.
	- 근데 여기서 1번 스레드는 다른 작업하다가 특정 메모리를 참조해야 하는데, 2번 스레드의 초기 작업중 그 특정 메모리를 1번 스레드 참조 타이밍 보다 빠르게 실행되면 GC로 인해 값은 사라진다.
	- 이를 Race Condition 이라고 한다.
- 결국 GIL 때문에 동시에 코드를 돌리는 스레드를 코딩해서 사용해도 오히려 gil을 넘겨주는 작업 등이 늘어나 싱글 스레드일 때보다 시간이 오래 걸린다.

**멀티 스레딩 사용 방법**
- gil 때문에 멀티스레드를 활용한 동시성 방법이 별로면 등장하지도 않았을 것 이다.
- 연산 같은 경우 끝임 없이 메모리를 들여다 보고 업데이트한다. 그렇기에 CPU를 사용한 연산 작업 시에는 gil을 사용한다.
- 즉 반대로 **메모리에 접근하지 않는 작업이 주인 경우, GIL을 굳이 오래 잡을 필요 없는 멀티 스레딩은 매우 효과적인 동시 작동 방법**이 된다.
- 대표적으로 파일 Load, DB I/O, 네트워크 통신 같은 작업이 주인 코드를 실행할 때는 실제 데이터가 네트워크나 OS의 커널을 타고 올라오는 즉 파이썬 엔진을 타지 않는 경우 해당 값을 들고 오고 객체에 해당 값을 저장할 때(메모리에 입력 시킬 때)만 GIL이 필요하다.
- 요약 하면 **I/O 작업이 큰 비중을 차지하거나 통신이 필요해 sleep으로 일정 시간 대기해야 하는 경우 멀티 스레딩은 매우 효과 적이다.**

**GIL 우회법**(동시 작업을 위해 사용하지 않는 방법)
- 가장 대표적인 방법은 **멀티 프로세싱을 사용**하는 방법이다.
	- 메모리를 공유안하니 굳이 락을 걸 필요가 없다.
	- 하지만 컨택스트 스위칭 비용은 CPU 용량을 많이 잡아먹는다.(데이터를 다른 메모리로 이동 시켜야하니)
- 또 다른 방법은 **CPython이 아닌 다른 인터프리터를 사용하는 방법이다.**
> [!CPython이란?]
> 컴파일(코드를 한번에 읽음) 형식이 아닌 인터프린터 형식(코드를 한 줄씩 읽음)인 파이썬이 표준 구현체이다. 
C언어를 Python으로 구현한 구현체이며, CPython 자체는 컴파일러지만 이 컴파일 코드를 이용해 인터프린터 형식인 Python을 구동시키는 거다. 즉 Python 코드를 bytecode로 컴파일한 후 해당 bytecode 형식 일땐 한 줄씩 실행시키기 때문이다. GIL은 CPython의 가장 대표적인 특성이다.
- 그래서 뭔말이냐면 파이썬 내부함수는 CPython 기반으로 코드가 짜였을거다.
- 그에 반해 Numpy나 PyTorch는 C로 컴파일된 순수 C언어 파이썬 패키지이다. 그래서 해당 패키지의 코드들은 GIL 관련 메모리 로직이 존재하지 않기에 사용 가능하다.
	- C 수준의 원시 코드라 원시 메모리에서 작업하기에 파이썬 객체 메모리에서 작업 안해서 가능
